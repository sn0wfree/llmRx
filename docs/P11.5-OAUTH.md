# P11.5 — MCP client OAuth

## 1. Why now

MCP 2025-06 spec 要求 client 支持 OAuth 2.1：授权服务器元数据
（RFC 8414）、动态 client 注册（RFC 7591）、设备授权码流
（RFC 8628）。当前 llmRx 对 MCP 服务器的认证只有静态
`Authorization` 头直传，无法连接需要 OAuth 的远程 MCP 服务器
（GitHub、Slack、Google 等 2025+ 的 MCP endpoint 大多走 OAuth）。

P11 把 OAuth 列为 P11.5 搁置项，现在补上。

## 2. What OAuth for MCP looks like

MCP 服务器暴露 `/.well-known/oauth-authorization-server`，返回：

```json
{
  "issuer": "https://api.example.com",
  "authorization_endpoint": "https://api.example.com/oauth/authorize",
  "token_endpoint": "https://api.example.com/oauth/token",
  "registration_endpoint": "https://api.example.com/oauth/register",
  "device_authorization_endpoint": "https://api.example.com/oauth/device"
}
```

客户端流程（client 模式，无浏览器回调环境）：

1. **发现**：GET `/.well-known/oauth-authorization-server`
   （带 `.mcp` 后缀变体：`/.well-known/oauth-authorization-server.mcp`，
   部分服务器用这个）。
2. **注册**：无 `client_id` 时 POST `registration_endpoint`（RFC 7591，
   `client_name` + 空 redirect_uris → 设备码流不需要回调）。
3. **授权**：POST `device_authorization_endpoint` → 拿 `user_code` +
   `verification_uri` + `interval`；用户打开 URL 输入 code 授权。
4. **换 token**：轮询 `token_endpoint`（grant_type=urn:ietf:params:oauth:grant-type:device_code）
   直到 `authorization_pending` → `access_token` + `refresh_token`。
5. **使用 + 刷新**：`Authorization: Bearer <access_token>`；过期
   用 `refresh_token` 换新的（grant_type=refresh_token）。

## 3. Scope

| Feature | In scope |
|---|---|
| 授权服务器元数据发现（RFC 8414，含 `.mcp` 变体） | ✅ |
| 动态 client 注册（RFC 7591） | ✅ |
| 设备授权码流（RFC 8628） | ✅ |
| access token 自动注入 + refresh 续期 | ✅ |
| 懒授权：401 触发（首次 ListTools/CallTool） | ✅ |
| Web UI 主动授权入口（展示 user_code + 验证 URL） | ✅ |
| token 加密存储（复用 `internal/secrets`） | ✅ |

Out of scope：授权码流（`authorization_code`，需浏览器回调，MCP
client 场景罕见）、PKCE（设备码流不需要）、token 撤销。

## 4. Design

### 4.1 状态机

每个启用 OAuth 的 MCP server 有一个授权状态：

```
pending → discovering → registered → authorizing (user_code 展示中)
       → ready (有可用 access_token) → expired → refreshing → ready
       ↘ failed (带错误，可重试)
```

状态存内存（ClientManager 内）+ 持久化 token（DB）。重启后从
DB 恢复 `ready`（refresh_token 有效）或 `pending`。

### 4.2 新增文件 `internal/mcp/oauth.go`

```go
// OAuthState 描述一次授权流程的当前状态，供 UI 查询。
type OAuthState struct {
    ServerID    int64
    Status      string // pending | authorizing | ready | failed
    UserCode    string
    VerificationURI string
    ExpiresIn   int
    Error       string
}

type OAuthManager struct {
    repo   store.MCPRepository
    secrets *secrets.Manager
    states sync.Map // serverID → *oauthSession
}

// Authorize 启动设备码流；返回 OAuthState（含 user_code）。
func (m *OAuthManager) Authorize(ctx context.Context, server *store.MCPServer) (*OAuthState, error)
// Poll 轮询 token 端点，拿到 token 后持久化。
func (m *OAuthManager) Poll(ctx context.Context, serverID int64) (*OAuthState, error)
// Token 返回有效的 access token（必要时用 refresh_token 续期）。
func (m *OAuthManager) Token(ctx context.Context, serverID int64) (string, error)
```

### 4.3 Client 集成

`Client` 加可选 `tokenProvider func(ctx context.Context) (string, error)`：

```go
type Client struct {
    transport     transport
    tokenProvider func(ctx context.Context) (string, error) // nil = 静态头
}
```

`rpc()` 里：

1. `tokenProvider == nil` → 用静态 `authHdr`（现状）。
2. 否则 `tok, err := tokenProvider(ctx)`；`Authorization: Bearer <tok>`。
3. 收到 `401` 且 `tokenProvider != nil` → 触发一次
   `oauthManager.Poll`/续期重试（最多 1 次），失败返回
   `mcp: auth required`，agentic loop 记 error。

### 4.4 存储

```sql
ALTER TABLE mcp_servers ADD COLUMN oauth_config_json TEXT NOT NULL DEFAULT '{}';
ALTER TABLE mcp_servers ADD COLUMN token_json TEXT NOT NULL DEFAULT '';
```

- `oauth_config_json`：`{"client_id":"","client_secret":"","scopes":[]}`
  （空 client_id → 动态注册）。
- `token_json`：加密后的 `{"access_token":"","refresh_token":"",
  "expires_at":unix,"token_type":"Bearer"}`，经 `secrets.Manager`
  AES-256-GCM 加密落库；读取时解密。
- 迁移用 `addColumnIfMissing`。

### 4.5 Web UI

`/admin/mcp-servers` 每行加"OAuth 授权"按钮：

1. 点击 → `POST /admin/mcp-servers/{id}/oauth/authorize` → 展示
   `user_code` + `verification_uri`（大号等宽字体）+ "已授权？检查状态"。
2. `GET /admin/mcp-servers/{id}/oauth/status` → 轮询状态
   （`ready` → 绿标"已授权"，`expires_at` 展示）。
3. 服务器表单加"OAuth 配置 (JSON)"输入框（可选，留空则动态注册）。

### 4.6 ClientManager 集成

```go
type ClientManager struct {
    ...
    oauth *OAuthManager // nil = 未启用 OAuth
}
```

`GetClient` 构造时：若 `server.OAuthConfigJSON` 非空
（`client_id` 或动态注册配置）→ `NewClient(url, "", oauth.tokenProviderFor(serverID))`。

## 5. Wire format

全部为标准 OAuth 2.0 form-encoded POST / JSON GET，无自定义协议。

## 6. Tests

- `oauth_test.go`：
  - **发现 + 动态注册**：httptest 模拟 `.well-known` + registration
    endpoint，断言请求形状 + client_id 持久化。
  - **设备码流全流程**：模拟 device endpoint + token endpoint，
    `authorization_pending` → poll → access_token。
  - **401 触发懒授权**：Client rpc 收到 401 → 调 provider 续期 →
    重试成功。
  - **refresh 续期**：expires_at 过期 → refresh_token 换新。
  - **token 加密往返**：`secrets.Manager` 加密写 DB → 解密读回。
- 现有 `client_test.go`（静态头）保持通过。

## 9. New dependencies

- 无第三方依赖。标准库 `net/http` + `crypto/rand`（PKCE 用）。
- 复用 `internal/secrets`（AES-256-GCM）。

2. Client `tokenProvider` 注入 + 401 重试。

## 11. Risks

| Risk | Mitigation |
|---|---|
| 服务器只支持授权码流（无 device endpoint） | 检测 `device_authorization_endpoint` 缺失 → 明确报错，文档说明 |
| token 端点限流/慢 | 轮询按 `interval`（默认 5s）退避，超时 5min 报 `authorization timeout` |
| refresh_token 也过期 | 清状态回 `pending`，UI 提示重新授权 |
| 动态注册被服务器拒绝 | 允许管理员手动填 `client_id`/`client_secret`（oauth_config_json） |
