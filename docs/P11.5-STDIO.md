# P11.5 — MCP stdio transport

## 1. Why now

P11 交付了 MCP **client** 模式（HTTP+SSE）和 **server** 模式
（`POST /mcp/llmrx`）。外部 MCP 服务器有两类：

- **远程**：HTTP+SSE（已支持）
- **本地 sidecar**：stdio 子进程（未支持）——典型场景是
  `npx @modelcontextprotocol/server-github` 这类以本地命令启动的
  MCP server，没有 HTTP 端点

没有 stdio，llmRx 无法消费这些 sidecar server 的工具。P11 把它列为
P11.5 搁置项，现在补上。

## 2. What is stdio transport

MCP 客户端作为**父进程**启动 server 子进程，通过 stdin/stdout 交换
JSON-RPC 消息：

```
llmRx (client, parent)
   │ fork+exec "npx @modelcontextprotocol/server-github"
   ▼
child process (MCP server)
   stdin  ← JSON-RPC request（每帧一行 JSON）
   stdout → JSON-RPC response（每帧一行 JSON）
```

帧格式分两代：

| 版本 | 帧格式 |
|---|---|
| MCP ≤ 2024-11 | 每帧一行 JSON，以 `\n` 结尾 |
| MCP 2025-03+ | `Content-Length: <n>\n\n<json>`（与 LSP 相同） |

需要同时支持，自动检测：stdout 首字符是 `{` → 行模式；是 `Content-Length` → 帧模式。

## 3. Scope

| Feature | In scope |
|---|---|
| `Client` 抽 transport 接口（`rpc` 与传输解耦） | ✅ |
| `stdioTransport`：`exec.Command` + stdin/stdout 行/帧读写 | ✅ |
| 请求串行化（JSON-RPC id 匹配） + context 取消 kill 进程 | ✅ |
| 子进程生命周期管理（懒启动、`Close`/`Invalidate` 时终止） | ✅ |
| store：`MCPServer` 加 `transport` + `command` 字段 + 迁移 | ✅ |
| Web UI：MCP 服务器表单支持传输类型/命令 | ✅ |
| 工具刷新 `RefreshTools` 复用同一 transport | ✅ |

Out of scope：server 模式暴露 stdio（llmRx 作为被启动的 MCP server，
没有宿主场景）、`initialization` 握手（2025-06 spec 保留字，我们的
协议栈无需）。

## 4. Design

### 4.1 Transport 接口

```go
// internal/mcp/client.go
type transport interface {
    rpc(ctx context.Context, method string, params map[string]any) (json.RawMessage, error)
    Close() error
}
```

- `httpTransport`：现 `Client.rpc` 逻辑原样搬入（`POST baseURL` +
  静态 `Authorization` 头）。
- `stdioTransport`：新实现。

`Client` 改为持有 `transport`，`NewClient(baseURL, authHdr)` 构造
httpTransport；`NewStdioClient(command string, args []string)` 构造
stdioTransport。`ListTools`/`CallTool` 不变（它们只调 `rpc`）。

### 4.2 stdioTransport 实现

```go
// internal/mcp/stdio.go
type stdioTransport struct {
    cmd      *exec.Cmd
    stdin    io.WriteCloser
    stdout   *bufio.Scanner
    mu       sync.Mutex   // 串行化请求
    stderr   io.Reader    // 透传到日志
    closeOnce sync.Once
}
```

`rpc(ctx, method, params)`：

1. `mu.Lock()` 串行化（一个子进程同一时刻只处理一个请求）。
2. `cmd` 未启动则 `exec.Command("sh", "-c", command)` 懒启动
   （`sh -c` 支持 `npx xxx`、管道、环境变量展开）。
3. 写帧到 stdin：行模式 `json\n`；帧模式
   `Content-Length: <n>\n\n<json>`。写失败 → 杀进程。
4. 从 stdout 读一帧，按首字符检测模式，解析 `Response`。
5. `ctx` 取消 → `cmd.Process.Kill()`，返回 `context.Canceled`。
6. stderr 行透传到 `logging`（server 的日志在 stderr）。

stdout 行长上限：MCP tool 结果可能很大，Scanner buffer 上限设
`16 MiB`（超限报错并杀进程防失控）。

### 4.3 生命周期

- `ClientManager.GetClient`：`MCPServer.Transport == "stdio"` 时
  `NewStdioClient(Command)`；否则 `NewClient`（现状）。
- `ClientManager.Invalidate(serverID)`：`Close()` 杀子进程并移除
  缓存（现有逻辑，`Close` 从关 http 连接改为调 transport.Close）。
- 启动失败（如 `npx` 不存在）：`rpc` 返回错误，工具调用走 agentic
  loop 的 error 分支（现有行为）。

### 4.4 存储

```sql
ALTER TABLE mcp_servers ADD COLUMN transport TEXT NOT NULL DEFAULT 'http';
ALTER TABLE mcp_servers ADD COLUMN command TEXT NOT NULL DEFAULT '';
```

- `transport`：`http` | `stdio`（默认 `http`，兼容存量）。
- `command`：stdio 的启动命令（如
  `npx @modelcontextprotocol/server-github`）；http 时为空。
- 存量迁移用现有 `addColumnIfMissing` 模式。
- `MCPServer` 结构体加 `Transport string` + `Command string`；
  CRUD SQL 同步（Create/Update/List/Get/GetEnabled）。

### 4.5 Web UI

`internal/webui/templates/mcp_servers/list.html` 添加表单：

- 传输类型下拉：`http`（默认）/ `stdio`
- `stdio` 时显示"启动命令"输入框
- 服务器表格加"传输"列（http → 显示 URL；stdio → 显示命令）

`mcp_servers.go` 的 `MCPServerCreate` 解析 `transport` + `command`。

## 5. Wire format

stdio 请求/响应与 HTTP 完全相同的 JSON-RPC 载荷（复用
`internal/mcp/protocol.go` 的 `Request`/`Response`），唯一差异是
帧编解码。

## 6. Tests

- `stdio_test.go`：
  - **行模式往返**：测试内起一个读 stdin 写 stdout 的 `exec.Command`
    （如 `cat` 或自写小 Go 二进制），验证 `ListTools`/`CallTool`
    JSON-RPC 形状。
  - **帧模式往返**：`Content-Length` 帧 server（测试内 `io.Pipe`
    对模拟），验证帧编解码。
  - **context 取消**：server 不响应时 cancel → 进程被 kill、返回
    `context.Canceled`。
  - **请求串行化**：并发 5 个 `rpc`，server 侧断言无交错。
  - **命令不存在**：`NewStdioClient("/nonexistent/cmd")` → rpc 报错。
- `client_test.go`：transport 接口抽后原 HTTP 测试保持通过。
- store 迁移测试：`addColumnIfMissing` 对存量 `mcp_servers` 表生效。
