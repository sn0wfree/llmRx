# llmRx 多例模式架构设计

## 一、概述

本文档描述 llmRx 多例模式的架构设计，包括自动注册、服务发现、负载均衡和容错机制。

### 1.1 设计目标

1. **去中心化**: 无外部依赖（数据库、Redis 等）
2. **自动注册**: 新节点自动加入集群
3. **高可用**: 主节点故障不影响服务
4. **内网安全**: 节点管理 API 仅内网访问

### 1.2 适用场景

- 中大规模部署
- 需要高可用的生产环境
- 需要动态扩缩容的场景

## 二、架构设计

### 2.1 整体架构

```
┌─────────────────────────────────────────────────────────┐
│                    Nginx (动态配置)                     │
│                    1核 2GB 内存                         │
│                                                         │
│  功能:                                                  │
│  - 动态发现节点                                         │
│  - 负载均衡                                             │
│  - 健康检查                                             │
│  - 内网访问控制                                         │
└─────────────────────────────────────────────────────────┘
                          │
          ┌───────────────┼───────────────┐
          ▼               ▼               ▼
┌─────────────────┐ ┌─────────────────┐ ┌─────────────────┐
│    llmRx-1     │ │    llmRx-2     │ │    llmRx-3     │
│   (主节点)     │ │   (从节点)     │ │   (新节点)     │
│                │ │                │ │                │
│  - 管理节点表  │ │  - 转发注册    │ │  - 自动注册    │
│  - 处理心跳    │ │  - 处理心跳    │ │  - 发送心跳    │
│  - 提供节点列表│ │                │ │                │
└────────┬───────┘ └────────┬───────┘ └────────┬───────┘
         │                  │                  │
         └──────────────────┼──────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│                  PostgreSQL (单节点)                    │
│                                                         │
│  存储: 用户数据、配置数据                               │
│  不存储: 节点注册信息 (内存管理)                        │
└─────────────────────────────────────────────────────────┘
```

### 2.2 节点角色

| 角色 | 职责 | 说明 |
|------|------|------|
| **主节点** | 管理节点注册表 | 第一个启动的节点 |
| **从节点** | 转发注册请求 | 帮助新节点找到主节点 |
| **新节点** | 自动注册 | 启动时自动加入集群 |

## 三、自动注册机制

### 3.1 注册流程

```
新节点启动流程:
┌─────────────────────────────────────────────────────────┐
│  1. 读取配置文件，判断模式                              │
│     ↓                                                   │
│  2. 如果是 cluster 模式，启动自动注册                   │
│     ↓                                                   │
│  3. 连接 PostgreSQL                                     │
│     ↓                                                   │
│  4. 启动 HTTP 服务                                      │
│     ↓                                                   │
│  5. 访问种子节点，获取节点列表                          │
│     ↓                                                   │
│  6. 找到主节点，发送注册请求                            │
│     ↓                                                   │
│  7. 主节点验证并存储节点信息                            │
│     ↓                                                   │
│  8. 启动心跳机制                                        │
│     ↓                                                   │
│  9. Nginx 自动发现节点                                  │
└─────────────────────────────────────────────────────────┘
```

### 3.2 主节点选举

```
主节点选举机制:
┌─────────────────────────────────────────────────────────┐
│  1. 第一个启动的节点自动成为主节点                      │
│     ↓                                                   │
│  2. 主节点维护节点注册表 (内存)                         │
│     ↓                                                   │
│  3. 其他节点定期向主节点发送心跳                        │
│     ↓                                                   │
│  4. 如果主节点挂了，其他节点感知到                      │
│     ↓                                                   │
│  5. 最早启动的从节点自动成为新主节点                    │
│     ↓                                                   │
│  6. 新主节点接管节点管理                                │
└─────────────────────────────────────────────────────────┘
```

### 3.3 心跳机制

```
心跳流程:
┌─────────────────────────────────────────────────────────┐
│  1. 从节点定期发送心跳到主节点                          │
│     ↓                                                   │
│  2. 主节点更新节点状态                                  │
│     ↓                                                   │
│  3. 如果心跳超时，标记节点离线                          │
│     ↓                                                   │
│  4. 主节点广播节点状态变化                              │
│     ↓                                                   │
│  5. 从节点更新本地缓存                                  │
└─────────────────────────────────────────────────────────┘
```

## 四、路由设计

### 4.1 路由结构

```
外部路由 (公网):
├── /v1/*          - LLM API
├── /admin/*       - 管理界面
├── /account/*     - 用户界面
└── /health        - 健康检查

内部路由 (内网):
└── /nodes/*       - 节点管理
    ├── /register  - 注册
    ├── /heartbeat - 心跳
    ├── /          - 列表
    └── /{id}      - 详情
```

### 4.2 访问控制

```
访问控制流程:
┌─────────────────────────────────────────────────────────┐
│  1. 请求到达                                            │
│     ↓                                                   │
│  2. 检查请求路径                                        │
│     ↓                                                   │
│  3. 如果是 /nodes/* 路径:                               │
│     ├─ 检查来源 IP 是否为内网                           │
│     ├─ 如果是内网，允许访问                             │
│     └─ 如果是外网，拒绝访问 (403)                       │
│     ↓                                                   │
│  4. 如果是其他路径:                                     │
│     ├─ 检查授权/登录状态                                │
│     └─ 正常处理                                         │
└─────────────────────────────────────────────────────────┘
```

## 五、容错机制

### 5.1 主节点故障

```
主节点故障处理:
┌─────────────────────────────────────────────────────────┐
│  1. 从节点检测到主节点心跳超时                          │
│     ↓                                                   │
│  2. 从节点宣布主节点离线                                │
│     ↓                                                   │
│  3. 最早启动的从节点自动成为新主节点                    │
│     ↓                                                   │
│  4. 新主节点接管节点管理                                │
│     ↓                                                   │
│  5. 其他节点重新注册到新主节点                          │
│     ↓                                                   │
│  6. Nginx 自动发现新主节点                              │
└─────────────────────────────────────────────────────────┘
```

### 5.2 网络分区

```
网络分区处理:
┌─────────────────────────────────────────────────────────┐
│  1. 节点检测到网络分区                                  │
│     ↓                                                   │
│  2. 分区内的节点继续提供服务                            │
│     ↓                                                   │
│  3. 分区恢复后，节点重新同步状态                        │
│     ↓                                                   │
│  4. 冲突解决：以最新时间戳为准                          │
└─────────────────────────────────────────────────────────┘
```

## 六、配置文件

### 6.1 节点配置

```yaml
# config.yml

# 存储模式: single (SQLite) | cluster (PostgreSQL + 自动注册)
storage:
  mode: cluster

# 单例模式配置
sqlite:
  dsn: /data/llmrx.db

# 多例模式配置
cluster:
  # PostgreSQL 连接
  database:
    url: postgres://llmrx:password@postgres:5432/llmrx?sslmode=disable
  
  # 当前节点配置
  node:
    id: "llmrx-3"
    address: "llmrx-3"
    port: 8787
    role: "replica"
    node_type: "api"
  
  # 种子节点
  seed_nodes:
    - "llmrx-1:8787"
    - "llmrx-2:8787"
  
  # 自动注册配置
  auto_register:
    enabled: true
    heartbeat_interval: 10s
    heartbeat_timeout: 5s
    node_timeout: 30s
```

## 七、部署方式

### 7.1 单例模式

```bash
docker run -d \
  -e STORAGE_MODE=single \
  -e DATABASE_DSN=/data/llmrx.db \
  llmrx:latest
```

### 7.2 多例模式

```bash
docker run -d \
  -e STORAGE_MODE=cluster \
  -e DATABASE_URL=postgres://llmrx:pass@postgres:5432/llmrx \
  -e SEED_NODES=llmrx-1:8787,llmrx-2:8787 \
  llmrx:latest
```
